# Python 性能基准测试套件

本目录包含一套完整的 Python 性能基准测试，帮助开发者理解和比较不同编程技术的性能差异。

## 目录结构

```
08_benchmarks/
├── 01_gil_benchmark.py          # GIL性能对比测试
├── 02_data_structure_benchmark.py  # 数据结构性能对比测试

├── 05_numpy_benchmark.py        # NumPy向量化对比测试

```

## 测试内容说明

### 1. GIL性能对比 (01_gil_benchmark.py)

测试 Python 全局解释器锁对多线程性能的影响。

**测试项目：**
- 单线程执行
- 2线程并行执行
- 4线程并行执行

**预期性能数据（参考）：**

| 测试项目 | 预期耗时 | 预期加速比 |
|---------|---------|-----------|
| 单线程 | ~0.5秒 | 1.0x |
| 2线程 | ~0.6秒 | ~0.8x |
| 4线程 | ~0.7秒 | ~0.7x |

**结论：** 由于 GIL 的存在，多线程在 CPU 密集型任务中无法获得线性加速，甚至可能变慢。


### 2. 数据结构性能对比 (02_data_structure_benchmark.py)

对比 List、Set、Dict 三种数据结构在常见操作下的性能。

**测试项目：**
- List: 创建、查找（开头/末尾）、追加、头部插入
- Set: 创建、查找、添加、交集运算
- Dict: 创建、按键查找、设置值、遍历键

**预期性能数据（参考，100万元素）：**

| 数据结构 | 操作 | 预期耗时 | 说明 |
|---------|------|---------|------|
| List | 追加 | ~0.01毫秒 | O(1) |
| List | 头部插入 | ~1毫秒 | O(n)，需要移动元素 |
| List | 查找（开头） | ~0.001毫秒 | O(n)但很快找到 |
| List | 查找（末尾） | ~10毫秒 | O(n)需要遍历整个列表 |
| Set | 查找 | ~0.001毫秒 | O(1)哈希表 |
| Set | 交集 | ~50毫秒 | O(min(n,m)) |
| Dict | 查找键 | ~0.001毫秒 | O(1)哈希表 |
| Dict | 遍历键 | ~30毫秒 | O(n) |

**结论：**
- 哈希表结构（Set/Dict）的查找性能远优于 List
- List 的头部插入性能极差，应避免频繁操作
- Set 的集合运算效率很高


### 3. 循环优化对比 (03_loop_benchmark.py)

比较不同循环写法的性能差异。

**测试项目：**
- 纯Python for循环
- while循环
- 列表推导式
- 生成器表达式
- 内置函数 map + filter

**预期性能数据（参考，100万次迭代）：**

| 测试项目 | 预期耗时 | 预期加速比 |
|---------|---------|-----------|
| 纯Python循环 | ~0.15秒 | 1.0x |
| while循环 | ~0.18秒 | ~0.8x |
| 列表推导式 | ~0.08秒 | ~1.8x |
| 生成器表达式 | ~0.10秒 | ~1.5x |
| 内置函数map+filter | ~0.12秒 | ~1.2x |

**结论：**
- 列表推导式性能最优，应优先使用
- 纯 Python 循环性能较差
- 生成器表达式略慢于列表推导式，但内存占用更低


### 4. Numba加速对比 (04_numba_benchmark.py)

使用 Numba JIT 编译器加速 Python 代码的效果。

**测试项目：**
- 纯Python计算
- Numba JIT 模式
- Numba NJIT（nopython）模式
- Numba Parallel 并行模式

**预期性能数据（参考，500万次计算）：**

| 测试项目 | 预期耗时 | 预期加速比 |
|---------|---------|-----------|
| 纯Python | ~0.5秒 | 1.0x |
| Numba JIT | ~0.01秒 | ~50x |
| Numba NJIT | ~0.005秒 | ~100x |
| Numba Parallel | ~0.002秒 | ~250x |

**结论：**
- Numba 可以带来数量级的性能提升
- NJIT 模式比 JIT 模式更快
- 并行模式在多核 CPU 上能获得额外加速


### 5. NumPy向量化对比 (05_numpy_benchmark.py)

对比纯 Python 循环与 NumPy 向量化操作的性能差异。

**测试项目：**
- 纯Python逐元素运算
- NumPy逐元素向量化运算
- 纯Python矩阵乘法
- NumPy矩阵乘法
- NumPy广播运算

**预期性能数据（参考，200x200矩阵）：**

| 测试项目 | 预期耗时 | 预期加速比 |
|---------|---------|-----------|
| 纯Python逐元素 | ~0.02秒 | 1.0x |
| NumPy逐元素 | ~0.0001秒 | ~200x |
| 纯Python矩阵乘法 | ~3秒 | 1.0x |
| NumPy矩阵乘法 | ~0.001秒 | ~3000x |
| NumPy广播运算 | ~0.0002秒 | ~100x |

**结论：**
- NumPy 向量化操作比纯 Python 快数百到数千倍
- 矩阵乘法的优化效果最为显著
- 应尽可能使用 NumPy 进行数值计算


### 6. 并发性能对比 (06_concurrency_benchmark.py)

比较不同并发模型在 CPU 密集和 IO 密集任务中的表现。

**测试项目（CPU密集）：**
- 顺序执行
- 多线程
- 多进程

**测试项目（IO密集）：**
- 顺序执行
- 多线程
- asyncio 异步

**预期性能数据（参考）：**

**CPU 密集任务（4个任务）：**

| 测试项目 | 预期耗时 | 预期加速比 |
|---------|---------|-----------|
| 顺序执行 | ~0.8秒 | 1.0x |
| 多线程 | ~0.9秒 | ~0.9x |
| 多进程 | ~0.25秒 | ~3.2x |

**IO 密集任务（10个任务，每个0.1秒）：**

| 测试项目 | 预期耗时 | 预期加速比 |
|---------|---------|-----------|
| 顺序执行 | ~1.0秒 | 1.0x |
| 多线程 | ~0.1秒 | ~10x |
| asyncio | ~0.1秒 | ~10x |

**结论：**
- CPU 密集任务应使用多进程
- IO 密集任务使用多线程或 asyncio 都能获得良好加速
- 多线程在 CPU 密集任务中因 GIL 限制无法有效加速

## 性能优化建议总结

基于上述测试结果，给出以下性能优化建议：

1. **数据结构选择：**
   - 需要频繁查找时，优先使用 Set 或 Dict
   - List 适合顺序访问，避免在头部频繁插入/删除

2. **循环优化：**
   - 优先使用列表推导式
   - 使用内置函数（map, filter）替代手动循环

3. **数值计算：**
   - 数值计算优先使用 NumPy 向量化操作
   - 对于循环密集的计算，考虑使用 Numba

4. **并发策略：**
   - CPU 密集任务：使用 multiprocessing
   - IO 密集任务：使用 threading 或 asyncio

5. **GIL 问题：**
   - 多线程不适合 CPU 密集型任务
   - 考虑使用多进程或 C 扩展绕过 GIL
