## 1. 列表推导 vs for 循环

### 原理
列表推导在 Python 底层是用 C 实现的，比解释器层面的 for 循环快得多。它避免了多次方法查找和函数调用开销。

### 代码对比
```python
# 慢：for 循环 + append
result = []
for i in range(1000):
    result.append(i * 2)

# 快：列表推导
result = [i * 2 for i in range(1000)]
```

### 性能数据
| 方法 | 执行时间 | 相对性能 |
|------|---------|----------|
| for 循环 + append | ~45-55 μs | 1.0x |
| 列表推导 | ~20-25 μs | **2.0-2.5x** |

**优化效果**: 提升 50-60%

### 最佳实践
- 优先使用列表推导代替 `for + append`
- 避免在列表推导中写复杂逻辑（可读性优先）

## 2. map/filter vs 循环

### 原理
`map` 和 `filter` 也是用 C 实现的内置函数，但配合 `lambda` 时会有额外开销。通常列表推导在大多数场景下表现更好。

### 代码对比
```python
# 慢：for 循环过滤 + 转换
result = []
for i in range(1000):
    if i % 2 == 0:
        result.append(i * 3)

# 中：filter + map（lambda 有开销）
result = list(map(lambda x: x * 3, filter(lambda x: x % 2 == 0, range(1000))))

# 快：列表推导 + 条件
result = [i * 3 for i in range(1000) if i % 2 == 0]
```

### 性能数据
| 方法 | 执行时间 | 相对性能 |
|------|---------|----------|
| for 循环过滤+转换 | ~55-65 μs | 1.0x |
| filter + map (lambda) | ~45-55 μs | ~1.2x |
| 列表推导 + 条件 | ~25-30 μs | **2.0-2.2x** |

**优化效果**: 列表推导提升 50-55%

### 最佳实践
- 简单操作优先用列表推导
- `map`/`filter` 配合内置函数（非 lambda）时性能更好
- 如：`list(map(str.upper, words))`

## 3. 内置函数优先

### 原理
Python 内置函数（如 `sum`, `max`, `min`, `all`, `any`）全部用 C 实现，避免了 Python 层的循环开销。

### 代码对比
```python
# 慢：手动循环求和
total = 0
for num in data:
    total += num

# 快：内置 sum() 函数
total = sum(data)

# 慢：手动循环求最大值
max_val = 0
for num in data:
    if num > max_val:
        max_val = num

# 快：内置 max() 函数
max_val = max(data)
```

### 性能数据
| 方法 | 执行时间 | 相对性能 |
|------|---------|----------|
| 手动循环求和 | ~35-45 μs | 1.0x |
| 内置 sum() | ~3-5 μs | **8-12x** |
| 手动循环求最大值 | ~30-40 μs | 1.0x |
| 内置 max() | ~2-4 μs | **10-15x** |

**优化效果**: 内置函数提升 80-95%

### 常用内置函数列表
- `sum()` - 求和
- `max()`/`min()` - 最大/最小值
- `all()` - 全部为真
- `any()` - 至少一个为真
- `sorted()` - 排序
- `zip()` - 并行迭代

## 4. 避免全局变量查找

### 原理
Python 查找变量的顺序是：局部 → 闭包 → 全局 → 内置。全局变量查找比局部变量慢。

### 代码对比
```python
import math

# 慢：每次循环都查找全局的 math.sin
result = []
for x in data:
    result.append(math.sin(x))

# 快：先将函数赋值给局部变量
local_sin = math.sin
result = []
for x in data:
    result.append(local_sin(x))
```

### 性能数据
| 方法 | 执行时间 | 相对性能 |
|------|---------|----------|
| 使用全局 math.sin | ~130-150 μs | 1.0x |
| 使用局部 sin 引用 | ~110-125 μs | **1.1-1.3x** |

**优化效果**: 提升 15-20%

### 最佳实践
- 循环内多次访问的全局变量，先赋值给局部变量
- 模块级的函数/常量在循环外局部化

## 5. 使用局部变量

### 原理
属性查找（如 `list.append`）也是有开销的。在循环中，每次 `append` 调用都需要重新查找方法。

### 代码对比
```python
# 较慢：每次循环都查找 append 方法
result = []
for i in range(1000):
    result.append(i)

# 较快：先将 append 方法赋值给局部变量
result = []
append = result.append
for i in range(1000):
    append(i)
```

### 性能数据
| 方法 | 执行时间 | 相对性能 |
|------|---------|----------|
| 循环内 append 方法查找 | ~40-50 μs | 1.0x |
| 局部引用 append 方法 | ~35-40 μs | **1.1-1.3x** |

**优化效果**: 提升 10-20%

### 注意
- 这种优化对高频循环有意义
- 不要为了微优化牺牲代码可读性
- 现代 Python 版本对此优化的效果越来越小

## 6. 循环展开

### 原理
循环展开通过减少循环次数和条件检查来提高性能。CPU 可以更好地进行指令级并行。

### 代码对比
```python
# 普通循环
total = 0
for i in range(1000):
    total += i

# 展开 4 次
total = 0
for i in range(0, 1000, 4):
    total += i
    total += i + 1
    total += i + 2
    total += i + 3
```

### 性能数据
| 方法 | 执行时间 | 相对性能 |
|------|---------|----------|
| 普通循环 | ~35-45 μs | 1.0x |
| 展开 2 次 | ~30-35 μs | ~1.2x |
| 展开 4 次 | ~25-30 μs | **1.4-1.6x** |
| 展开 8 次 | ~22-26 μs | **1.5-1.8x** |

**优化效果**: 展开 4 次提升 30-40%

### 最佳实践
- 展开因子通常取 4 或 8（缓存友好）
- 确保循环次数能被展开因子整除（或处理余数）
- 不要过度展开（代码膨胀反而降低性能）

## 7. 生成器表达式节省内存

### 原理
列表推导会一次性生成所有元素并存储在内存中。生成器表达式惰性求值，只在需要时计算。

### 代码对比
```python
# 内存占用大：列表推导
total = sum([i * 2 for i in big_data])  # 先创建完整列表

# 内存占用小：生成器表达式
total = sum(i * 2 for i in big_data)  # 流式计算，无中间列表
```

### 性能数据
| 指标 | 列表推导 | 生成器表达式 |
|------|---------|-------------|
| 10000 元素内存 | ~85KB | ~112 bytes |
| 性能 | 基准 (1.0x) | 略慢 5-15% |
| 内存节省 | - | **99.9%** |

**优化效果**: 内存节省 > 99%（大数据集）

### 适用场景
- 处理大数据集或流式数据
- 只需迭代一次的场景
- 链式计算（如 `sum(map(f, filter(g, data)))`）

## 8. itertools 高效迭代

### 原理
`itertools` 模块提供了一系列用 C 实现的迭代器工具，专门为高效迭代设计。

### 代码对比
```python
import itertools

# 慢：嵌套循环计算笛卡尔积
result = []
for i in range(100):
    for j in range(100):
        result.append((i, j))

# 快：itertools.product
result = list(itertools.product(range(100), range(100)))

# 慢：手动链化多个列表
lists = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
result = []
for sublist in lists:
    result.extend(sublist)

# 快：itertools.chain.from_iterable
result = list(itertools.chain.from_iterable(lists))
```

### 性能数据
| 方法 | 执行时间 | 相对性能 |
|------|---------|----------|
| 嵌套循环笛卡尔积 | ~350-450 μs | 1.0x |
| itertools.product | ~150-200 μs | **2.0-2.5x** |
| 手动 extend 链化 | ~60-80 μs | 1.0x |
| itertools.chain | ~30-40 μs | **2.0x** |

**优化效果**: 提升 50-60%

### 常用 itertools 函数
| 函数 | 用途 |
|------|------|
| `product` | 笛卡尔积 |
| `chain` / `chain.from_iterable` | 链式迭代 |
| `combinations` | 组合 |
| `permutations` | 排列 |
| `islice` | 切片迭代器 |
| `groupby` | 分组 |

### 优化优先级建议
1. **最高优先级**: 使用内置函数和列表推导
2. **高优先级**: 使用生成器处理大数据，使用 itertools
3. **中优先级**: 局部变量优化（性能关键代码）
4. **低优先级**: 循环展开（仅极端性能要求场景）

### 代码优化示例对比
```python
# ❌ 未优化版本（最慢）
total = 0
for i in range(1000000):
    if math.sqrt(i) > 10:
        total += math.sin(i)

# ✅ 优化版本（最快）
import math
sqrt = math.sqrt
sin = math.sin
total = sum(sin(i) for i in range(1000000) if sqrt(i) > 10)
```

**性能差异**: 优化后可提升 **3-5 倍**

## 最佳实践总结

### 编写高效循环的 8 条黄金法则

1. **能用内置函数，绝不手动写循环**
2. **优先使用列表推导/生成器表达式**
3. **大数据集用生成器，小数据集用列表**
4. **复杂迭代用 itertools**
5. **循环内的全局变量/方法先局部化**
6. **避免在循环内进行属性查找**
7. **极端性能场景考虑循环展开**
8. **优先保证可读性，再考虑微优化**

### 记住
> "过早优化是万恶之源" — Donald Knuth

- 先让代码工作，再让它快速
- 用性能分析工具（如 `cProfile`）找到瓶颈
- 只对真正的热点代码进行优化
