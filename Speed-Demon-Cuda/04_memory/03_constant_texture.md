# 常量内存与纹理内存

## 常量内存 (Constant Memory)

### 什么是常量内存

常量内存是 GPU 上的一种特殊只读内存，具有以下特点：

- **容量**: 每个 GPU 通常 64KB
- **访问速度**: 比全局内存快，接近共享内存
- **缓存机制**: 每个 SM 有独立的常量缓存
- **广播特性**: 一次读取可广播给整个 warp
- **只读**: 只能从主机端写入，设备端只读

### 常量内存的适用场景

1. **固定参数**: 卷积核、变换矩阵、配置参数
2. **小而频繁访问的数据**: 所有线程都需要访问相同的数据
3. **Warp 广播优化**: 当 warp 内所有线程访问同一地址时

### 性能优势

| 特性 | 全局内存 | 常量内存 |
|-----|---------|---------|
| 容量 | 很大 (GB) | 很小 (64KB) |
| 访问延迟 | 高 (400-800 cycles) | 低 (~100 cycles) |
| 带宽 | 高 | 更高（缓存） |
| 广播支持 | 无 | 自动广播给 warp |

## 纹理内存 (Texture Memory)

### 什么是纹理内存

纹理内存最初是为图形渲染设计的，也可用于通用计算：

- **基于纹理缓存**: 特殊的 2D 局部性缓存
- **空间局部性优化**: 相邻线程访问相邻地址时效率高
- **滤波支持**: 内置线性、双线性滤波
- **边界处理**: 自动处理边界条件（钳制、环绕、镜像）

### 纹理内存的适用场景

1. **图像处理**: 图像滤波、卷积操作
2. **数据访问具有 2D 局部性**: 相邻像素访问
3. **需要滤波插值**: 数据重采样、缩放
4. **不规则访问模式**: 随机但空间相关的访问

### 纹理内存的限制

- **设置复杂**: 需要绑定、解绑操作
- **只读**: 不能写入纹理内存
- **格式限制**: 支持的数据类型有限
- **现代 GPU 影响**: 在最新架构上优势减弱

## 性能对比表格

| 内存类型 | 容量 | 延迟 | 带宽 | 读写 | 最佳使用场景 |
|---------|------|------|------|------|-------------|
| 寄存器 | 极小 | 极低 | 极高 | 读写 | 临时变量 |
| 共享内存 | ~48KB/block | 低 | 高 | 读写 | 线程间共享数据 |
| 常量内存 | 64KB | 低 | 高 | 只读 | 固定参数、warp 广播 |
| 纹理内存 | 很大 | 中 | 高 | 只读 | 2D 局部性访问 |
| 全局内存 | 很大 | 高 | 中 | 读写 | 大量数据存储 |

## 使用示例

### 常量内存使用

```cpp
// 声明常量内存
__constant__ float d_kernel[KERNEL_SIZE];

// 主机端初始化
cudaMemcpyToSymbol(d_kernel, h_kernel, sizeof(d_kernel));

// 设备端使用
__global__ void convolution(const float* input, float* output)
{
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    float sum = 0.0f;
    for (int k = 0; k < KERNEL_SIZE; ++k) {
        sum += input[idx + k - HALF_SIZE] * d_kernel[k];
    }
    output[idx] = sum;
}
```

### 纹理内存使用 (CUDA 早期版本)

```cpp
// 声明纹理引用
texture<float, cudaTextureType2D, cudaReadModeElementType> tex_ref;

// 主机端绑定
cudaChannelFormatDesc channelDesc = cudaCreateChannelDesc<float>();
cudaBindTexture2D(&tex_ref, d_image, &channelDesc, width, height, pitch);

// 设备端读取
__global__ void filter_kernel(float* output)
{
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    float val = tex2D(tex_ref, x, y);
    output[y * width + x] = val;
}

// 解绑
cudaUnbindTexture(tex_ref);
```

### 现代替代方案

在现代 CUDA 编程中，推荐：

1. **`__restrict__` 限定符**: 帮助编译器优化指针别名
2. **合并访问**: 正确的内存访问模式
3. **共享内存**: 显式控制数据缓存
4. **统一内存 (UM)**: 简化编程模型

## 最佳实践总结

### 常量内存使用建议

✅ **优先用于小的只读数据**（小于 64KB）  
✅ **所有线程访问相同数据时使用**（利用广播）  
✅ **卷积核、变换矩阵等固定参数**  
❌ **不要用于大量数据**（容量限制）  
❌ **不要用于线程访问不同地址的情况**（失去广播优势）

### 纹理内存使用建议

✅ **图像处理和 2D 数据**  
✅ **具有空间局部性的不规则访问**  
✅ **需要插值或滤波操作**  
❌ **简单的顺序访问**（合并访问更高效）  
❌ **需要写入的数据**

### 一般建议

1. **测量，不要猜测**: 使用 Profiler 验证优化效果
2. **组合使用**: 常量内存 + 共享内存 + 合并访问
3. **注意架构差异**: 不同 GPU 架构性能特性不同
4. **现代 GPU 趋势**: L1/L2 缓存越来越大，专用内存优势减弱

## 常见问题

**Q: 常量内存只能存 64KB，超过怎么办？**  
A: 可以拆分成多个内核，或者使用只读的全局内存配合 `const` 限定符。

**Q: 纹理内存和常量内存哪个更快？**  
A: 取决于访问模式。所有线程访问相同地址时常量内存更快；有 2D 局部性时纹理内存更快。

**Q: 在 Ampere 及以后架构上还需要使用纹理内存吗？**  
A: 可能不需要。新的 L2 缓存更大，直接使用合并的全局内存访问通常足够高效。

**Q: 如何验证常量缓存是否命中？**  
A: 使用 NVIDIA Nsight Compute 查看 `constant_mem_cache_hit_rate` 指标。
