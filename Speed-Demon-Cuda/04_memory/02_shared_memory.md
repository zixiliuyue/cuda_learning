# 共享内存优化 (Shared Memory Optimization)

## 共享内存的正确使用

### 什么是共享内存

共享内存是位于每个 Streaming Multiprocessor (SM) 上的高速片上存储器，具有以下特点：

- **延迟**: ~10-20 个时钟周期（全局内存 ~400-800）
- **带宽**: ~100 TB/s（远高于全局内存）
- **容量**: 每个 SM 通常 48-164 KB
- **可见性**: 仅对同一个线程块内的线程可见

### 共享内存的典型用途

1. **数据复用**: 线程间共享数据，减少全局内存访问
2. **分块计算**: 将大问题分成小块，使数据适应共享内存
3. **线程间通信**: 实现归约、扫描等协作算法

## Bank 冲突的避免

### 什么是 Bank

共享内存被分成 32 个（或更多）等宽的内存模块，称为 Bank。每个 Bank 可以独立服务一个请求。

- **Bank 宽度**: 通常为 4 字节（一个 float）
- **地址映射**: `bank = address / 4 % 32`

### Bank 冲突的类型

| 冲突类型 | 说明 | 有效带宽 |
|---------|------|---------|
| 无冲突 | 每个线程访问不同的 Bank | 100% |
| 2-way | 每 Bank 有 2 个线程访问 | 50% |
| 4-way | 每 Bank 有 4 个线程访问 | 25% |
| 广播 | 所有线程访问同一地址 | 100% (特殊情况) |

### 避免 Bank 冲突的方法

#### 方法 1: 填充 (Padding)
```cpp
// 有冲突
__shared__ float sh[32][32];  // sh[0][0] 和 sh[1][0] 在同一 Bank

// 无冲突
__shared__ float sh[32][33];  // 增加 1 列填充，错开 Bank 映射
```

#### 方法 2: 调整访问模式
```cpp
// 有冲突：线程 tid 访问 sh[tid][0]
float val = sh[threadIdx.x][0];

// 无冲突：线程 tid 访问 sh[0][tid]
float val = sh[0][threadIdx.x];
```

#### 方法 3: 使用向量化访问
```cpp
// 使用 float2 同时访问两个 Bank
float2 val = reinterpret_cast<float2*>(sh)[threadIdx.x];
```

## 分块（Tiling）技术

### 分块的核心思想

将大矩阵分成多个小方块（Tile），使得：
1. 每个 Tile 能完全放入共享内存
2. 计算时只访问共享内存，减少全局内存访问

### 分块矩阵乘法的原理

**常规矩阵乘法 (C = A × B)**:
- 每个元素计算需要 2N 次全局内存访问
- 总访问次数: O(N³)

**分块矩阵乘法**:
- 将 Tile 加载到共享内存（一次全局访问）
- 在 Tile 内重复使用数据
- 总访问次数: O(N³ / TILE_SIZE)

### 分块大小选择

| 因素 | 建议 |
|-----|------|
| 共享内存容量 | TILE_SIZE² × sizeof(float) ≤ 共享内存/块 |
| Bank 冲突 | TILE_SIZE 建议为 16、32 |
| 占用率 | 保证足够的线程块数 |

**典型分块大小**: 16×16, 32×32

## 共享内存最佳实践

1. ✅ **优先使用共享内存**缓存重复访问的数据
2. ✅ 选择合适的分块大小（16×16 或 32×32）
3. ✅ 使用填充技术避免 Bank 冲突
4. ✅ 合并共享内存访问
5. ✅ 及时同步 (`__syncthreads()`)
6. ❌ 避免共享内存的过度使用影响占用率
7. ❌ 不要在共享内存中存储只访问一次的数据

## 常见陷阱

| 问题 | 原因 | 解决方法 |
|-----|------|---------|
| 结果错误 | 缺少同步 | 在读写共享内存之间添加 `__syncthreads()` |
| 性能低下 | Bank 冲突 | 添加填充或调整访问模式 |
| 内核不启动 | 共享内存超限 | 减小分块大小 |
| 结果部分正确 | 边界条件未处理 | 检查 Tile 是否超出矩阵边界 |
