# 合并内存访问 (Coalesced Memory Access)

## 什么是合并访问

合并内存访问是 CUDA 编程中最重要的性能优化技术之一。当一个 warp 内的所有线程访问全局内存时，如果它们的访问地址满足特定条件，GPU 硬件会将这些独立的内存访问请求合并成一个或几个连续的内存事务，从而大大提高内存带宽利用率。

### 核心概念

- **Warp**: GPU 执行的基本单元，包含 32 个线程
- **内存事务**: 一次内存读写操作，通常为 32、64 或 128 字节
- **合并**: 将多个线程的内存请求合并为更少的事务

## 合并访问的条件

### 计算能力 2.0+ (Fermi 及以上)

1. **对齐要求**: 内存访问地址对齐到缓存行边界 (128 字节)
2. **连续访问**: warp 内线程访问连续的内存地址
3. **线程索引映射**: 线程 k 访问地址 base + k 或类似线性模式

### 现代 GPU (计算能力 5.0+)

条件相对宽松，但保持连续访问仍然是最佳实践。

## 非合并访问的性能影响

### 性能对比（理论）

| 访问模式 | 事务数量 | 带宽利用率 |
|---------|---------|-----------|
| 完全合并 | 1 | 100% |
| 步长 2 | 2 | 50% |
| 步长 4 | 4 | 25% |
| 随机访问 | 32 | ~3% |

### 实际影响

- 带宽限制的内核性能可能下降 10 倍以上
- 内存控制器利用率低下
- 功耗增加

## 优化方法

### 1. 调整数据布局

**优化前 (AoS)**:
```cpp
struct Particle {
    float x, y, z;
    float vx, vy, vz;
};
Particle particles[N];  // 访问 x 时步长为 6
```

**优化后 (SoA)**:
```cpp
struct Particles {
    float x[N], y[N], z[N];
    float vx[N], vy[N], vz[N];
};  // 访问 x 时连续
```

### 2. 使用正确的索引模式

**优化前**:
```cpp
int idx = blockIdx.x * blockDim.x + threadIdx.x;
float val = array[idx * stride];  // 非连续
```

**优化后**:
```cpp
int idx = blockIdx.x * blockDim.x + threadIdx.x;
float val = array[idx];  // 连续访问
```

### 3. 向量化加载

使用 `float2`, `float4` 等向量类型提高合并效率。
