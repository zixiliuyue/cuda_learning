## 0. 文档目的与范围

对 `QingTian/web` 前端控制台进行一次系统性代码检查，识别工程层面的问题，实施**低风险、零新增依赖**的优化，并沉淀可执行的后续改进清单。

**检查范围**（全部源码通读）：
- 构建与配置：`vite.config.js`、`package.json`、`index.html`
- 应用骨架：`main.js`、`App.vue`、`router/index.js`
- 网络层：`api/request.js`、`api/index.js`
- 页面视图：`Login.vue`、`Layout.vue`、`Dashboard.vue`、`Nodes.vue`、`Tasks.vue`

**技术栈现状**：Vue 3.5 + Vue Router 4 + Pinia 2（已安装）+ Arco Design Vue 2.57 + Axios 1.7 + Vite 5.4。

---

## 1. 核心结论

一句话判断：**功能闭环完整、代码整洁，但在"首屏性能、状态管理、网络层健壮性、部署可配置性"四个工程维度上存在明确短板。** 本次优化已修复其中风险最低、收益最高的部分，其余列入后续改进清单。

最大亮点问题：项目**已安装 Pinia 却完全未使用**，认证状态靠各组件直接读写 `localStorage`，同时**生产构建为单一 951 KB 巨包、零代码分割**。这两点是本次优化的重点。

## 2. 问题诊断结果

按严重程度与维度分类。`状态` 列标注本次是否已处理。

### 2.1 性能（Performance）

| 编号 | 问题描述 | 影响 | 严重度 | 状态 |
|------|---------|------|--------|------|
| P-1 | 生产构建无代码分割，全部打成单个 `index.js`（951 KB / gzip 288 KB），首屏需下载全部 JS | 首屏加载慢，弱网体验差；业务代码微小改动即导致含 UI 库的整包缓存失效重下 | 高 | ✅ 已修复 |
| P-2 | 路由组件在 `router/index.js` 顶部静态 `import`，登录页也会加载全部业务页代码 | 未登录用户被迫下载受保护页面代码 | 高 | ✅ 已修复 |
| P-3 | 第三方依赖（Arco/Vue/Axios）与业务代码混在同一 chunk，无法利用长期缓存 | 缓存命中率低，重复下载 | 中 | ✅ 已修复（manualChunks 分包） |
| P-4 | Arco Design 全量注册（`app.use(ArcoVue)` + 全量 CSS 402 KB），实际仅用十余个组件 | 首屏 JS/CSS 体积仍偏大 | 中 | ⏳ 列入后续（需按需引入插件） |

### 2.2 健壮性（Robustness）

| 编号 | 问题描述 | 影响 | 严重度 | 状态 |
|------|---------|------|--------|------|
| R-1 | `request.js` 响应拦截器直接 `resp.data.data`，未校验后端统一结构 `{code,message,data}`；`code!=OK` 但 HTTP 200 的业务失败不会被识别 | 业务错误被当成功、`undefined` 向下游传播引发页面崩溃 | 高 | ✅ 已修复 |
| R-2 | 各页面 `nodes.value = await api.list()` 未校验返回是否为数组，接口异常返回对象时 `.filter/.reduce` 抛错 | 页面白屏 | 中 | ✅ 已修复（Dashboard/Nodes 加数组守卫） |
| R-3 | 任务提交按钮无防重复提交（无 loading 态），弹窗在请求失败时仍关闭，需重填 | 重复提交、表单数据丢失 | 中 | ✅ 已修复（`on-before-ok` + `confirm-loading`） |
| R-4 | 取消任务无二次确认，误点即取消且不可撤销 | 误操作损失 | 中 | ✅ 已修复（`Modal.warning` 确认） |
| R-5 | 无路由兜底（404 未匹配），错误 hash 进入空白 | 体验差 | 低 | ✅ 已修复（catch-all 重定向） |

### 2.3 安全（Security）

| 编号 | 问题描述 | 影响 | 严重度 | 状态 |
|------|---------|------|--------|------|
| S-1 | 令牌 key `'qt_token'` 字符串在 `request.js`/`router`/`Login`/`Layout` 四处硬编码，改动易遗漏 | 维护风险，登出/失效清理不彻底 | 中 | ✅ 已修复（常量 + Pinia 统一管理） |
| S-2 | JWT 存于 `localStorage`，存在 XSS 窃取风险 | 令牌泄露 | 中 | ⏳ 列入后续（评估 httpOnly Cookie 方案） |
| S-3 | 登录守卫仅判断 token 是否存在，不校验有效性/过期 | 过期 token 仍可进入页面直到首个 401 | 低 | ⏳ 列入后续（引入过期时间判断） |

### 2.4 工程化与可维护性（Maintainability）

| 编号 | 问题描述 | 影响 | 严重度 | 状态 |
|------|---------|------|--------|------|
| M-1 | 已安装 Pinia 但零使用，认证状态散落在各组件直接读写 `localStorage` | 状态分散、逻辑重复、易出错 | 高 | ✅ 已修复（新增 `store/auth.js`） |
| M-2 | 后端地址在代码中隐式固定，无环境变量，无法区分测试/生产 | 部署需改代码 | 中 | ✅ 已修复（`VITE_API_BASE` + `.env.example`） |
| M-3 | 无 ESLint / Prettier / 单元测试，缺少质量门禁 | 代码风格漂移、回归无保护 | 中 | ⏳ 列入后续 |
| M-4 | 页面标题固定，切换路由不更新 `document.title` | 多标签页难辨识 | 低 | ✅ 已修复（`afterEach` 动态标题） |
| M-5 | `index.html` 缺 `description`/`theme-color`/`noscript` | SEO/可访问性/降级体验缺失 | 低 | ✅ 已修复 |

### 2.5 响应式与可用性（UX）

| 编号 | 问题描述 | 影响 | 严重度 | 状态 |
|------|---------|------|--------|------|
| U-1 | Dashboard 统计卡片写死 `:cols="5"`，窄屏严重挤压 | 移动端/小窗不可用 | 中 | ✅ 已修复（响应式断点 xs/sm/md/lg） |
| U-2 | Dashboard 无加载态与刷新入口 | 数据陈旧、无反馈 | 低 | ✅ 已修复（`a-spin` + 刷新按钮） |
| U-3 | 登录后无法回跳到原访问页面 | 体验割裂 | 低 | ✅ 已修复（`redirect` query） |

## 3. 优化实施步骤

按实施顺序记录，均为**零新增依赖**改动（Pinia 原已安装）。

### 步骤 1：新建认证状态 Store（M-1 / S-1）
- 新增 `src/store/auth.js`，使用 Pinia setup 语法集中管理 `token` / `user`，暴露 `isAuthenticated`、`username`、`setAuth()`、`clear()`。
- 统一 `TOKEN_KEY`/`USER_KEY` 常量，安全解析用户 JSON（异常回退空对象）。

### 步骤 2：网络层堅牢化（R-1 / S-1 / M-2）
- 重写 `src/api/request.js` 响应拦截器：校验统一结构 `{code,message,data}`，`code!=='OK'` 判定为业务失败并 reject；兼容裸数据返回。
- 超时 10s → 15s；`baseURL` 改为读取 `import.meta.env.VITE_API_BASE`，缺省回退 `/api/v1`。
- 401 时统一清除 token/user 并跳登录；忽略被取消请求避免误报。

### 步骤 3：路由懒加载 + 守卫增强（P-2 / R-5 / M-4 / U-3）
- `router/index.js` 全部视图改为动态 `import()`，按路由代码分割。
- 增加 catch-all 兜底路由、登录回跳 `redirect` query、已登录访问登录页自动跳首页。
- `afterEach` 依据 `meta.title` 动态更新页面标题。

### 步骤 4：Vite 生产分包（P-1 / P-3）
- `vite.config.js` 增加 `build.rollupOptions.output.manualChunks`，将 `vue/vue-router/pinia`、`@arco-design/web-vue`、`axios` 拆为独立 chunk；`chunkSizeWarningLimit` 提升至 800。

### 步骤 5：页面组件优化（R-2 / R-3 / R-4 / U-1 / U-2）
- `Login.vue`：接入 auth store，防重复提交，支持登录回跳。
- `Layout.vue`：用户名/登出改由 auth store 驱动，移除 localStorage 直读。
- `Dashboard.vue`：数组守卫、加载态 `a-spin`、刷新按钮、响应式栅格断点。
- `Nodes.vue`：返回值数组守卫。
- `Tasks.vue`：提交按钮 loading + `on-before-ok` 保持失败时弹窗不关；取消任务加 `Modal.warning` 二次确认。

### 步骤 6：静态资源与配置（M-2 / M-5）
- 新增 `web/.env.example` 说明 `VITE_API_BASE`。
- `index.html` 补充 `theme-color`、`description`、`noscript` 降级提示。

## 4. 优化前后对比数据

### 4.1 生产构建产物对比（`npm run build`，gzip 为传输体积）

| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| JS 产物结构 | 单文件 `index.js` | 按 vendor + 路由拆分为 15 个 chunk | 结构性改善 |
| 单包最大 JS | 951.35 KB（gzip 287.68 KB） | 787.80 KB arco（gzip 226.03 KB） | 拆分后可独立缓存 |
| 应用入口 JS | 951.35 KB（含全部） | 3.41 KB（gzip 1.71 KB） | ↓ 99.6% |
| Vue 运行时 chunk | 混入主包 | 107.97 KB（gzip 42.17 KB）独立 | 可长期缓存 |
| Axios chunk | 混入主包 | 46.09 KB（gzip 17.77 KB）独立 | 可长期缓存 |
| 首屏路由代码 | 全部页面一次加载 | 仅 Login 1.72 KB 按需 | 按需加载 |
| 业务页 chunk | 无独立 | Dashboard 2.11 / Nodes 1.25 / Tasks 4.70 KB | 访问时才拉取 |
| 构建是否通过 | ✅ | ✅ | 保持 |

> 关键收益：业务代码（占迭代改动 99%）修改后，仅重下 KB 级业务 chunk，占体积 90% 以上的 Arco/Vue vendor chunk 命中浏览器缓存无需重下——**二次访问与迭代发布的传输量下降一个数量级**。

### 4.2 代码质量指标对比

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| localStorage 直接读写点 | 6 处（散落 4 个文件） | 收敛至 1 个 store |
| token key 硬编码处 | 4 处 | 常量化 |
| 后端地址可配置 | 否（写死） | 是（环境变量） |
| 后端业务错误码识别 | 未识别 | 已识别并统一提示 |
| 接口异常防白屏守卫 | 无 | Dashboard/Nodes 已加 |
| 危险操作二次确认 | 无 | 取消任务已加 |
| 首屏响应式适配 | 固定 5 列 | xs/sm/md/lg 断点 |

## 5. 后续改进建议（按优先级）

### P0（建议尽快）
1. **Arco Design 按需引入**（P-4）：引入 `unplugin-vue-components` + Arco resolver，仅打包实际使用的组件，预计再降首屏 JS/CSS 50%+。
2. **引入 ESLint + Prettier**（M-3）：统一风格、CI 门禁，避免风格漂移。

### P1（近期规划）
3. **令牌安全加固**（S-2/S-3）：评估 httpOnly Cookie 或 refresh token 机制；前端解析 JWT `exp` 做过期预判，避免过期 token 进入页面。
4. **全局错误边界与骨架屏**：为懒加载路由增加 loading/错误占位，提升弱网体验。
5. **API 层抽象 TypeScript 类型**：为后端 DTO 建立类型定义，减少字段拼写与 undefined 问题。

### P2（长期）
6. **单元测试 + 组件测试**（Vitest + Vue Test Utils）：覆盖 request 拦截器、auth store、关键交互。
7. **可观测性**：接入前端错误监控（如 Sentry）与性能上报，闭环线上问题。
8. **无障碍与国际化**：完善 aria 属性，抽离文案支持 i18n。
