# QingTian 算力调度平台 —— 业务优化执行文档

> 文档性质：业务发展与用户价值提升的执行方案（Execution Doc）
> 评估基准：当前已实现的技术闭环 MVP（提交→调度→执行→回传 + 节点纳管 + RBAC + Web 控制台）

## 0. 文档目的

从业务发展和用户价值提升角度，对 QingTian 进行全面评估，识别业务痛点、优化机会与发展瓶颈，并给出可落地、带优先级的执行计划。本文档可直接用作产品/研发迭代的路线图依据。

---

## 1. 现状定位与核心结论

**一句话判断**：QingTian 已具备"能用"的调度内核，但距离"好用、想用、持续用、愿意付费"仍有明显差距。当前最大的业务风险不是技术，而是**缺乏差异化价值锚点与用户留存抓手**——它目前更像一个"GPU 任务提交器"，而非"帮用户省钱/提效的算力运营平台"。

**竞争参照系**：
- 上有 Kubernetes + Volcano/Kueue（开源标准）
- 下有各云厂商 GPU 弹性调度
- 旁有 Run:ai / 趋动科技 OrionX / 阿里 cGPU 等商业切分方案

若不建立差异点，极易陷入"重复造轮子"。

**战略主线（贯穿全文）**：
> 把叙事从"我能调度 GPU"转向"我帮你把 GPU 利用率翻倍、并让每一分算力花得明明白白"。

## 2. 分维度评估

### 维度 1：用户体验流程优化

| 问题描述 | 优化方向 | 预期业务收益 | 优先级 |
|---------|---------|-------------|--------|
| 任务提交需手填镜像/命令/资源，门槛高；无实时日志、无失败诊断 | 任务模板/一键复用、实时日志流(WebSocket)、失败原因结构化提示 | 提交成功率↑、用户挫败感↓、支持工单↓ | **P0** |
| 任务终态无制品下载入口，MinIO 能力未在前端暴露 | 前端接入结果/日志下载(预签名URL)、数据集上传 | 打通"数据进-算-果出"全流程，价值闭环 | **P0** |
| 无排队可见性：用户不知任务为何 pending、排第几、何时跑 | 展示队列位置、等待原因、资源缺口提示 | 降低焦虑与重复提交，减少"任务卡住"投诉 | **P1** |

> 洞察：AI/算力用户对"确定性"极敏感。"提交后黑盒等待"是最大体验硬伤。

### 维度 2：核心功能业务价值提升

| 问题描述 | 优化方向 | 预期业务收益 | 优先级 |
|---------|---------|-------------|--------|
| 调度只做整卡/显存软限，未做 GPU 共享(MIG/MPS/显存切片) | 引入细粒度切分调度（商业化核心卖点） | GPU 利用率 30%→70%+，直接=省钱 | **P0** |
| 无成本/计量视角，用户与管理者看不到"花了多少算力" | 用量计量、成本看板、配额预算 | 让"省钱"可量化，打动付费决策者 | **P1** |
| 长任务无 Checkpoint/断点续跑，节点宕机进度全丢 | 周期性 Checkpoint 到 MinIO + 断点重调度 | 训练类用户刚需，提升可靠性口碑 | **P1** |
| 无 Gang Scheduling，分布式训练无法整组调度 | 支持多卡/多节点成组调度 | 打开"大模型训练"高价值场景 | **P2** |

> 洞察：**GPU 共享 + 利用率可视化**是从"能调度"跃迁到"有商业价值"的关键分水岭。

### 维度 3：市场竞争力增强

| 问题描述 | 优化方向 | 预期业务收益 | 优先级 |
|---------|---------|-------------|--------|
| 与 K8s 生态平行造轮子，集成成本高、迁移意愿低 | 提供 K8s Operator/CRD 兼容层或明确"轻量非 K8s"定位 | 降低获客阻力，锁定中小团队 | **P1** |
| 无差异化标签，易被开源方案替代 | 聚焦垂直场景（高校实验室共享/推理弹性/渲染农场）做深 | 避开正面竞争，建立细分心智 | **P1** |
| 异构算力（国产 GPU/NPU）未支持，而这是国内政企痛点 | Agent 采集层抽象化，纳管昇腾/寒武纪等 | 契合信创需求，打开政企/高校市场 | **P2** |

> 战略建议：不要做"更差的 K8s"，要做"K8s 太重、云太贵"场景下的**最简私有化算力运营台**。

### 维度 4：用户留存与活跃度提升

| 问题描述 | 优化方向 | 预期业务收益 | 优先级 |
|---------|---------|-------------|--------|
| 无通知/告警，任务成败靠用户轮询 | 任务完成/失败通知（企业微信/飞书/邮件） | 提升日活粘性，平台主动触达 | **P1** |
| 无团队协作：任务/数据集不能共享，无项目空间 | 项目/团队工作区 + 资源共享 | 从个人工具升级为团队协作平台 | **P2** |
| 缺乏使用洞察，无法运营 | 埋点 + 个人/团队用量报告 | 数据驱动运营，识别高价值/流失用户 | **P2** |

### 维度 5：商业模式可持续性改进

| 问题描述 | 优化方向 | 预期业务收益 | 优先级 |
|---------|---------|-------------|--------|
| 无计费/配额，无法变现 | 按卡时/按用量计费 + 配额套餐 | 建立收入模型基础 | **P1** |
| 未区分开源版/企业版价值边界 | 开源核心引流 + 企业版（共享/多租户/审计/SSO）付费 | 可持续商业化路径（开源 PLG 打法） | **P2** |

### 维度 6：资源配置效率优化

| 问题描述 | 优化方向 | 预期业务收益 | 优先级 |
|---------|---------|-------------|--------|
| 调度器单实例串行决策，规模上有瓶颈 | 调度域分片 + 批量调度 | 支撑更大集群，避免规模天花板 | **P2** |
| 空闲卡无回收，能耗浪费 | 空闲检测 + 自动缩容/降功耗 | 降低运营成本，强化"省钱"叙事 | **P2** |
| 数据集重复从 MinIO 拉取 | 节点本地缓存 + 数据亲和调度 | 任务启动提速，I/O 成本↓ | **P2** |

## 3. 优先级执行路线图

### 第一波 —— P0（立刻做，决定"用户愿不愿意用"）

| 序号 | 事项 | 说明 |

## 4. 关键风险提示

| 风险 | 等级 | 说明 |
|------|------|------|
| 差异化风险 | **最高** | 不补 GPU 共享与成本可视化，无法回答"为何不用免费的 K8s+Volcano" |
| 数据闭环缺口 | 高 | MinIO 已接入但前端未暴露，"算力"与"数据"目前断裂 |
| 信任风险 | 高 | 无 Checkpoint、无通知、无排队可见性，专业用户会对可靠性失去信心 |
| 过度工程风险 | 中 | 获得真实用户反馈前，不宜投入 Gang Scheduling、多集群联邦等重功能，先验证 PMF |

---

## 5. 落地建议与下一步

**核心三件事（围绕战略主线优先推进）**：
1. GPU 共享调度（提利用率）
2. 数据闭环（上传/下载）
3. 成本可视化（用量/成本看板）

其余功能按用户反馈迭代。

**建议下一步**：从 P0 中选一项输出具体技术实现方案并落地到当前代码库。三个候选：
- 实时日志流（WebSocket + 日志归档 MinIO）
- GPU 共享调度（账本与调度器扩展支持显存切片/MIG）
- 成本计量（用量采集 + 成本看板 API + 前端页面）
