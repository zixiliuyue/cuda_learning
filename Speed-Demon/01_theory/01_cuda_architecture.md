# CUDA 架构原理 🚀

## 1. GPU vs CPU 架构对比 🆚

### 核心设计理念对比

| 特性 | CPU | GPU |
|------|-----|-----|
| 核心数量 | 少量高性能核心 (2-64) | 大量简单核心 (数千个) |
| 延迟优化 | ✅ 低延迟优先 | ✅ 高吞吐量优先 |
| 缓存大小 | 大缓存 (MB级) | 小缓存 (KB级) |
| 控制逻辑 | 复杂控制单元 | 简单控制单元 |
| 适用场景 | 串行任务、复杂逻辑 | 并行计算、数据密集型 |

### 架构示意图

```
CPU 架构 (延迟优化):
┌─────────────────────────────────────────┐
│              大缓存                      │
│  ┌───────────────────────────────────┐  │
│  │   L3 Cache (MB级)                 │  │
│  └───────────────────────────────────┘  │
│  ┌──────────┐  ┌──────────┐  ┌───────┐ │
│  │ 核心1    │  │ 核心2    │  │ 核心3 │ │
│  │ 复杂控制 │  │ 复杂控制 │  │ ...   │ │
│  └──────────┘  └──────────┘  └───────┘ │
└─────────────────────────────────────────┘

GPU 架构 (吞吐量优化):
┌─────────────────────────────────────────┐
│              SM集群                      │
│  ┌──────────┐  ┌──────────┐  ┌───────┐ │
│  │ SM 1     │  │ SM 2     │  │ SM n  │ │
│  │ 128核心  │  │ 128核心  │  │ ...   │ │
│  │ 简单控制 │  │ 简单控制 │  │       │ │
│  └──────────┘  └──────────┘  └───────┘ │
│  ┌───────────────────────────────────┐  │
│  │         全局内存 (GB级)            │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

## 2. SM (Streaming Multiprocessor) 架构 🔧

SM 是 GPU 的核心计算单元，每个 SM 包含：

### SM 内部组件

| 组件 | 功能 | 数量/大小 (Ampere) |
|------|------|-------------------|
| CUDA 核心 | 执行整数和浮点运算 | 128个 FP32核心 |
| Tensor 核心 | 加速矩阵运算 (AI) | 8个 |
| RT 核心 | 光线追踪加速 | 4个 |
| 寄存器文件 | 快速存储线程上下文 | 64KB - 256KB |
| 共享内存/L1缓存 | 线程块内共享数据 | 16KB - 164KB |
| L2 缓存 | SM间共享 | ~4MB - 40MB |
| Warp 调度器 | 调度线程束执行 | 4个 |
| 指令缓存 | 存储指令 | 专用 |

### SM 架构图

```
┌─────────────────────────────────────────────────┐
│              Streaming Multiprocessor (SM)       │
│                                                 │
│  ┌──────────────┐  ┌──────────────┐            │
│  │  Warp调度器1 │  │  Warp调度器2 │  ...       │
│  └──────────────┘  └──────────────┘            │
│                                                 │
│  ┌───────────────────────────────────────────┐  │
│  │              寄存器文件                     │  │
│  │         (64KB - 256KB per SM)             │  │
│  └───────────────────────────────────────────┘  │
│                                                 │
│  ┌───────────────────────────────────────────┐  │
│  │         共享内存 / L1 缓存                 │  │
│  │         (可配置 16KB - 164KB)             │  │
│  └───────────────────────────────────────────┘  │
│                                                 │
│  ┌───────┐ ┌───────┐ ┌───────┐ ┌───────────┐  │
│  │CUDA核心│ │Tensor核心│ │RT核心│ │ 特殊功能单元│ │
│  │ (128) │ │  (8)    │ │ (4)  │ │ (SFU)    │  │
│  └───────┘ └─────────┘ └───────┘ └───────────┘  │
└─────────────────────────────────────────────────┘
```

## 3. 线程层次结构：Grid/Block/Thread 📊

CUDA 使用三层线程层次结构来组织并行计算。

### 层次结构说明

```
┌─────────────────────────────────────────────────────────┐
│                      Grid (网格)                         │
│                                                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌─────────┐ │
│  │ Block 0  │  │ Block 1  │  │ Block 2  │  │ Block n │ │
│  │ (线程块) │  │ (线程块) │  │ (线程块) │  │  ...    │ │
│  └──────────┘  └──────────┘  └──────────┘  └─────────┘ │
│                                                         │
│  每个 Block 包含:                                        │
│  ┌─────────────────────────────────────────────────┐   │
│  │ Thread 0  Thread 1  Thread 2  ... Thread 31    │   │
│  │ Thread 32 Thread 33 Thread 34 ... Thread 63    │   │
│  │                    ...                         │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

### 各层次详细说明

| 层次 | 中文名称 | 说明 | 范围 | 内置变量 |
|------|---------|------|------|---------|
| Thread | 线程 | 最小执行单元 | 单个核心 | `threadIdx` |
| Block | 线程块 | 一组协同工作的线程，共享共享内存 | 单个SM | `blockIdx` |
| Grid | 网格 | 所有线程块的集合 | 整个GPU | `gridDim`, `blockDim` |

### 索引计算示例

```cpp
__global__ void kernel(float* data) {
    // 计算全局线程索引
    int threadId = blockIdx.x * blockDim.x + threadIdx.x;
    
    // 2D 索引计算
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;
}
```

### 常用配置维度

| 维度 | 最大限制 | 推荐大小 |
|------|---------|---------|
| Block 大小 | 1024线程 | 128, 256, 512 |
| Grid 大小 | 理论无上限 | 根据数据量调整 |

## 4. Warp 执行模型 ⚡

Warp (线程束) 是 SM 中执行和调度的基本单位。

### Warp 概念

- **大小**: 固定32个线程 (所有CUDA架构)
- **执行方式**: SIMT (单指令多线程)
- **调度单位**: Warp 是调度的最小单位

### Warp 执行示意

```
Warp 中的32个线程同步执行:

┌─────────────────────────────────────────────────────┐
│  Warp (32个线程)                                    │
│                                                     │
│  T0  T1  T2  T3  T4  T5  ... T31                   │
│  ↓   ↓   ↓   ↓   ↓   ↓       ↓                     │
│  ┌─────────────────────────────────────────────┐   │
│  │           同一条指令                         │   │
│  │      (不同数据，相同操作)                    │   │
│  └─────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

### Warp 调度机制

1. **指令获取**: Warp 调度器获取下一条指令
2. **操作数检查**: 检查操作数是否就绪
3. **发射执行**: 如果就绪，发射到执行单元
4. **上下文切换**: 不就绪时切换到其他 Warp

### 关键特性 ✨

| 特性 | 说明 |
|------|------|
| **SIMT 执行** | 32个线程执行相同指令，但操作不同数据 |
| **零开销切换** | Warp 切换不消耗额外周期 |
| **延迟隐藏** | 通过切换到其他 Warp 隐藏内存访问延迟 |
| **分支发散** | Warp 内线程分支不同时串行执行 |

## 5. 内存层次结构 💾

CUDA 拥有多层内存结构，各层有不同的特性和用途。

### 内存层次金字塔

```
                    ┌─────────────────┐
                    │   寄存器 (最快)  │  线程私有
                    │  ~1 cycle       │
                    └─────────────────┘
                  ┌─────────────────────┐
                  │  共享内存 / L1缓存  │  Block内共享
                  │    ~1-32 cycles     │
                  └─────────────────────┘
              ┌─────────────────────────────┐
              │         L2 缓存             │  SM间共享
              │       ~30-100 cycles        │
              └─────────────────────────────┘
          ┌─────────────────────────────────────┐
          │          全局内存 (最慢)             │  所有线程共享
          │        ~200-800 cycles             │
          └─────────────────────────────────────┘
```

### 各内存类型对比

| 内存类型 | 位置 | 作用域 | 生命周期 | 速度 | 容量 | 关键字 |
|---------|------|--------|---------|------|------|--------|
| 寄存器 | SM内 | 线程 | 内核执行 | ⚡ 最快 | KB级 | 自动分配 |
| 共享内存 | SM内 | Block | 内核执行 | ⚡ 很快 | 16-164KB | `__shared__` |
| L1缓存 | SM内 | SM | 动态 | ⚡ 很快 | 与共享内存共用 | 硬件管理 |
| L2缓存 | 跨SM | 全局 | 动态 | 快 | 4-40MB | 硬件管理 |
| 全局内存 | 板载 | 所有线程 | 应用程序 | 较慢 | GB级 | `__global__` |
| 常量内存 | 板载 | 所有线程 | 应用程序 | 较快 | 64KB | `__constant__` |
| 纹理内存 | 板载 | 所有线程 | 应用程序 | 较快 | GB级 | `texture<>` |
| 本地内存 | 板载 | 线程 | 内核 | 较慢 | 可变 | 寄存器溢出 |

### 内存访问优化策略 🎯

1. **寄存器优先**: 尽可能使用寄存器存储临时数据
2. **共享内存复用**: Block 内数据共享，减少全局内存访问
3. **合并访问**: 全局内存访问要对齐和连续
4. **利用缓存**: L1/L2 缓存可显著提升随机访问性能

## 总结 📝

| 概念 | 关键点 |
|------|--------|
| GPU vs CPU | GPU 吞吐量优先，CPU 延迟优先 |
| SM | GPU 的核心计算单元，包含大量核心和缓存 |
| 线程层次 | Grid → Block → Thread 三层结构 |
| Warp | 32线程一组，SIMT执行，调度基本单位 |
| 内存层次 | 寄存器 → 共享/L1 → L2 → 全局，速度递减容量递增 |

理解这些架构原理是编写高性能 CUDA 程序的基础！🎯
