## 核心概念

### 为什么激活需要「校准」？

```
训练好的 FP32 模型 ──> 权重直接量化（张量就在那，范围一看便知）
                     └> 激活范围依赖输入数据，未知！
                        └─ 用一小批「校准集」跑前向，收集各层激活分布 ──> 定 scale
```

权重是静态的，`max(|W|)` 直接可算；但激活 `y = Wx + b` 依赖输入 `x`，只有真正喂数据跑一遍才知道它的动态范围。这一步就是 **校准（calibration）**。

### 三种校准策略：如何选量化范围阈值 T？

| 策略 | 阈值 T 怎么选 | 特点 |
|------|--------------|------|
| **min/max** | `T = max(|act|)` | 简单，但离群值撑大范围，主体台阶变粗 |
| **percentile** | `T = |act| 的 99.9% 分位数` | 裁掉尾部离群值，主体量化更细 |
| **KL 散度** | 遍历候选 T，选使 `KL(P‖Q)` 最小 | 在裁剪误差与台阶误差间取最优折中 |

### KL 散度校准（TensorRT 熵校准）直觉

```
   量化误差
     ^
     |  \                      /
     |   \  裁剪误差主导      / 台阶误差主导
     |    \                  /
     |     \______________ /   <- 最优 T 在谷底
     +------------------------> 阈值 T
          T 太小            T 太大
     (裁掉太多信息)      (台阶太粗)
```

- **T 太小**：大量尾部质量被 clip 到边界，参考分布 P 严重失真 → KL 大。
- **T 太大**：128 个整数台阶要覆盖更宽的范围，量化粒度变粗 → KL 也大。
- 选 `KL(P‖Q)` 最小的 T，即最佳折中。实现上：P 是「尾部并入边界」的直方图，Q 是「压到 128 台阶再展开」的直方图。

### 评估指标：bulk-MSE

量化后**准确率**在小模型上往往三种校准都一样（都接近 FP32），不足以区分优劣。本天额外用 **bulk-MSE**（只统计主体 99% inlier 值的重建误差）来度量：percentile/KL 把范围收紧到主体，主体台阶更细，bulk-MSE 更小——**这正是大模型上精度差距的来源**。

## 知识点总结

1. **PTQ 定义**：训练后量化，不更新权重，只把权重/激活转 INT8，成本低、最常用。
2. **权重 vs 激活**：权重范围静态可算；激活范围需校准集估计。
3. **校准集**：几十~几百条代表性样本即可，无需标签（只跑前向收集激活）。
4. **min/max**：最简单，对离群值敏感，范围易被撑大。
5. **percentile**：裁掉尾部（如 99.9%），主体量化更精细。
6. **KL 散度**：遍历候选阈值，选量化前后分布 KL 最小者，TensorRT 默认策略。
7. **bulk-MSE**：只看主体重建误差，比准确率更能区分校准优劣。

## 验收标准

- 程序打印 KL 校准的「误差 U 型曲线」直觉，你能解释 T 过小/过大都不好。
- 三种校准的阈值 T 满足：`min/max ≥ percentile`，KL 落在合理区间。
- percentile 的 bulk-MSE 明显小于 min/max（把范围收紧到主体）。
- PTQ 后准确率相对 FP32 下降 < 5%，显示「通过 ✓」。

1. **改校准集大小**：把校准集从 256 改成 16 / 1024，观察阈值 T 是否稳定。
2. **加百分位档位**：加一个 99.0% 与 99.99% 的百分位校准，对比 bulk-MSE。
3. **INT4 校准**：把量化位宽改成 4bit（`QMAX=7`），观察三种校准的差距是否放大。
4. **权重也校准**：目前权重用 max，尝试对权重也做百分位裁剪，看是否有增益。

## 常见问题

- **Q：校准集需要标签吗？**
  A：不需要。校准只跑前向收集激活分布，与标签无关；标签只在最后评估精度时用。

- **Q：为什么小模型三种校准准确率一样？**
  A：小模型冗余大、类间间隔宽，量化噪声不足以翻转预测。大模型/长尾激活上差距才显现，故本天用 bulk-MSE 提前揭示差异。

- **Q：KL 校准为什么有时阈值偏小？**
  A：当激活有一个巨大的零值尖峰（如 ReLU 后），熵校准可能过度裁剪。工程上常先剔除零 bin 或改用百分位，这也是 percentile 更鲁棒的原因之一。
