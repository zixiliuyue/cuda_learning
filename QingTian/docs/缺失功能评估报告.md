# QingTian（擎天）平台缺失功能评估报告

**文档版本**: v1.0  
**评估日期**: 2026-07-21  
**评估范围**: 后端核心、前端控制台、基础设施集成

---

## 1. 执行摘要

### 1.1 当前成熟度评估

| 评估维度 | 成熟度 | 说明 |
|---------|--------|------|
| **单机调度能力** | 85% | 单机多卡调度、任务生命周期、资源账本基本完善 |
| **可观测性** | 80% | 日志流、计量计费、Dashboard 已具备 |
| **用户界面** | 75% | 核心功能界面完成，但缺少可视化编排 |
| **基础设施集成** | 30% | **最大短板**：缺少 Kubernetes 原生支持 |
| **分布式训练** | 20% | 仅单机调度，无多机多卡 Gang Scheduling |
| **多租户隔离** | 25% | 项目级隔离，缺少 Namespace/网络隔离 |

### 1.2 关键结论

> **核心判断**：QingTian 目前是一个**功能完整的单机 GPU 调度平台**，但要成为**企业级分布式 AI 基础设施**，必须补全 **Kubernetes 深度集成** 这一核心能力。

## 2. 缺失功能清单（按优先级排序）

### 🔴 P0 - 核心缺失（阻塞生产级部署）

**详细技术实现分析**：

```go
    TaskID         string    `json:"taskId,omitempty"`

    CompletionTime *metav1.Time `json:"completionTime,omitempty"`

// Reconcile 循环核心逻辑
func (r *TrainingJobReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
    // 1. 获取 TrainingJob CR
    var job qingtianiov1.TrainingJob
    if err := r.Get(ctx, req.NamespacedName, &job); err != nil {
        return ctrl.Result{}, client.IgnoreNotFound(err)
    }

    // 2. 根据 CR 状态同步到 QingTian Task
    switch job.Status.Phase {
    case "":
        // 新建任务，创建到 QingTian
        task := r.convertToTask(&job)
        if err := r.qingtianClient.CreateTask(ctx, task); err != nil {
            job.Status.Phase = "Failed"
            return ctrl.Result{}, err
        }
        job.Status.TaskID = task.ID
        job.Status.Phase = "Pending"
    case "Pending", "Running":
        // 从 QingTian 同步状态回 CR
        task, err := r.qingtianClient.GetTask(ctx, job.Status.TaskID)
        if err != nil {
            return ctrl.Result{}, err
        }
        r.syncStatus(&job, task)
    case "Failed", "Succeeded":
        // 终态，不需要处理
        return ctrl.Result{}, nil
    }

    // 3. 更新 CR status
    if err := r.Status().Update(ctx, &job); err != nil {
        return ctrl.Result{}, err
    }

    // 4. 继续重试直到终态
    if !IsTerminal(job.Status.Phase) {
        return ctrl.Result{RequeueAfter: 10 * time.Second}, nil
    }

    return ctrl.Result{}, nil
}
```

#### 2.2 Gang Scheduling（多机多卡分布式训练）

| 属性 | 说明 |
|------|------|
| **现状** | 仅支持单机多卡（单个 Pod/Container）|
| **缺失原因** | 调度器未实现 PodGroup / Gang Scheduling 语义 |
| **影响范围** | 无法运行需要多机通信的分布式训练（DDP、DeepSpeed、Horovod）|

**详细需求**：

```go
// 期望的 Gang Scheduling 语义
type PodGroup struct {
    Name string
    Spec PodGroupSpec
    Status PodGroupStatus
}

type PodGroupSpec struct {
    MinMember int32           // 最少需要调度的 Pod 数
    Scheduler string          // 使用哪个调度器
    PriorityClassName string  // 优先级
}

// 调度策略：All-or-Nothing
// 要么全部调度成功，要么一个都不调度
// 防止资源死锁（部分 Pod 占用资源等待其他 Pod，但其他 Pod 无法调度）
```

**实现方案**：

1. **集成 Volcano Scheduler**（推荐）
   - Volcano 是 CNCF 项目，原生支持 Gang Scheduling
   - 提供 PodGroup、Queue、Priority 等高级调度语义
   - 与 QingTian 调度器共存：Volcano 负责多机 Gang，QingTian 负责单机精细调度

2. **自研 Gang Scheduler**（备选）
   ```go
   // 核心逻辑：两阶段提交
   type GangScheduler struct {
       pendingGroups map[string]*PodGroup
       reservedNodes map[string][]string // group -> node list
   }

   func (gs *GangScheduler) Schedule(pg *PodGroup) error {
       // 阶段1：预留资源（不真正分配）
       nodes, err := gs.reserve(pg)
       if err != nil {
           return err // 资源不足，直接失败
       }
       
       // 阶段2：原子分配
       if err := gs.commit(pg, nodes); err != nil {
           gs.rollback(pg) // 回滚
           return err
       }
       return nil
   }
   ```

**预期收益**：
- 支持千亿参数大模型训练（需要 100+ GPU 分布式）
- 提高集群利用率（避免资源碎片导致的无法调度）
- 支持主流训练框架（PyTorch DDP、DeepSpeed、Megatron-LM、Horovod）

**详细技术实现分析**：

| 分析维度 | 具体内容 |
|---------|---------|
| **技术实现路径** | 1. 优先集成 Volcano Scheduler，复用其成熟的 Gang Scheduling 能力<br>2. 在 QingTian 侧定义 PodGroup 概念，对应一个分布式任务的所有 Pod<br>3. 实现 Volcano PodGroup 生命周期管理：创建 → 调度 → 销毁<br>4. 环境变量注入：为每个 replica 设置正确的 MASTER_ADDR、WORLD_SIZE 等<br>5. 自研方案采用两阶段提交：先预留资源，确认所有资源可用后再原子分配 |
| **所需资源** | - 开发：1 名后端工程师 × 4 周<br>- 测试：需要多节点 K8s 集群（至少 4 节点各 1 卡）<br>- 依赖：Volcano Scheduler 安装到集群 |
| **潜在风险** | 1. **资源死锁**：多个 Gang 互相等待对方释放资源<br>2. **Volcano 与 QingTian 调度冲突**：双调度器可能导致资源分配不一致<br>3. **调度延迟增加**：两阶段调度增加延迟<br>4. **少数失败导致全体重调度**：一个 Pod 调度失败整个 Gang 回滚 |
| **风险应对** | 1. 使用队列排序+老化机制，老任务优先级提升，避免饿死<br>2. Volcano 只做 Gang 调度决策，QingTian 做 GPU 拓扑亲和性调度，职责分离<br>3. 预留超时机制，长时间占用未分配自动回滚<br>4. 支持有限重试，失败快速回滚释放资源 |

**具体实现方案（Volcano 集成）**：

```go
// GangScheduler 封装 Volcano 集成
type VolcanoGangScheduler struct {
    k8sClient  kubernetes.Interface
    volcanoClient volcano.Clientset
    config      Config
}

type DistributedGangJob struct {
    Name         string
    Namespace    string
    Replicas     int
    TotalGPUs    int
    Priority     int32
    TaskSpec     *v1.PodTemplateSpec
}

// Schedule 提交一个 Gang Job 到 Volcano
func (s *VolcanoGangScheduler) Schedule(ctx context.Context, job *DistributedGangJob) error {
    // 1. 创建 PodGroup
    pg := &scheduling.PodGroup{
        ObjectMeta: metav1.ObjectMeta{
            Name:      job.Name,
            Namespace: job.Namespace,
            Labels: map[string]string{
                "qingtian.io/job": job.Name,
            },
        },
        Spec: scheduling.PodGroupSpec{
            MinMember:   job.Replicas,
            Queue:       "qingtian",
            Priority:    job.Priority,
        },
    }
    _, err := s.volcanoClient.SchedulingV1beta1().PodGroups(job.Namespace).Create(ctx, pg, metav1.CreateOptions{})
    if err != nil {
        return err
    }

    // 2. 创建所有 Pod，都打上 Volcano 调度标签
    for i := 0; i < job.Replicas; i++ {
        pod := buildPod(job, i)
        // 注入 Volcano 调度标签
        pod.Labels[volcano.PodGroupLabel] = job.Name
        pod.Spec.SchedulerName = "volcano"
        // 注入分布式训练环境变量
        injectEnv(pod, i, job.Replicas)
        _, err := s.k8sClient.CoreV1().Pods(job.Namespace).Create(ctx, pod, metav1.CreateOptions{})
        if err != nil {
            // 回滚已经创建的 Pod
            s.rollback(ctx, job)
            return err
        }
    }

    return nil
}

// 注入 PyTorch DDP 环境变量
func injectEnv(pod *v1.Pod, rank int, worldSize int) {
    pod.Spec.Containers[0].Env = append(pod.Spec.Containers[0].Env, v1.EnvVar{
        Name:  "RANK",
        Value: strconv.Itoa(rank),
    })
    pod.Spec.Containers[0].Env = append(pod.Spec.Containers[0].Env, v1.EnvVar{
        Name:  "WORLD_SIZE",
        Value: strconv.Itoa(worldSize),
    })
    pod.Spec.Containers[0].Env = append(pod.Spec.Containers[0].Env, v1.EnvVar{
        Name:  "MASTER_ADDR",
        Value: fmt.Sprintf("%s-0.%s-headless", pod.Name, pod.Name),
    })
    pod.Spec.Containers[0].Env = append(pod.Spec.Containers[0].Env, v1.EnvVar{
        Name:  "MASTER_PORT",
        Value: "23456",
    })
}
```

#### 2.3 多租户 Namespace/网络隔离

| 属性 | 说明 |
|------|------|
| **现状** | 仅有项目级逻辑隔离，无物理/网络隔离 |
| **缺失原因** | 未集成 Kubernetes NetworkPolicy / CNI 隔离 |
| **影响范围** | 无法保障多用户环境下的安全和资源隔离 |

**详细需求**：

```yaml
# 多租户隔离模型
---
# 1. Namespace 隔离
apiVersion: v1
kind: Namespace
metadata:
  name: team-a-project-1
  labels:
    qingtian.io/tenant: team-a
    qingtian.io/project: project-1
    qingtian.io/resource-quota: gpu-8

---
# 2. 资源配额
apiVersion: v1
kind: ResourceQuota
metadata:
  name: gpu-quota
  namespace: team-a-project-1
spec:
  hard:
    requests.nvidia.com/gpu: 8
    limits.nvidia.com/gpu: 8
    requests.memory: 128Gi

---
# 3. 网络隔离（NetworkPolicy）
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: team-a-project-1
spec:
  podSelector: {}
  policyTypes:
    - Ingress
    - Egress

---
# 4. 允许同项目内通信
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-same-project
  namespace: team-a-project-1
spec:
  podSelector:
    matchLabels:
      qingtian.io/project: project-1
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              qingtian.io/project: project-1
  egress:
    - to:
        - namespaceSelector:
            matchLabels:
              qingtian.io/project: project-1
```

**实现建议**：

1. **Namespace 自动管理**
   ```go
   type NamespaceManager struct {
       k8sClient kubernetes.Interface
   }

   func (nm *NamespaceManager) CreateWorkspace(tenant, project string) (*v1.Namespace, error) {
       ns := &v1.Namespace{
           ObjectMeta: metav1.ObjectMeta{
               GenerateName: fmt.Sprintf("%s-%s-", tenant, project),
               Labels: map[string]string{
                   "qingtian.io/tenant":  tenant,
                   "qingtian.io/project": project,
               },
           },
       }
       return nm.k8sClient.CoreV1().Namespaces().Create(context.TODO(), ns, metav1.CreateOptions{})
   }
   ```

2. **CNI 网络隔离**
   - 使用 Calico 或 Cilium 作为 CNI
   - 基于 Label 的 NetworkPolicy 自动生成
   - 支持跨 Namespace 通信白名单

3. **资源配额自动同步**
   - 当用户在控制台修改配额时，自动同步到 K8s ResourceQuota
   - 支持 GPU 显存配额（使用 Extended Resources）

**预期收益**：
- 满足金融/医疗等强隔离要求行业需求
- 防止租户间资源抢占和干扰
- 支持复杂的网络策略（如只允许访问特定存储）

**详细技术实现分析**：

| 分析维度 | 具体内容 |
|---------|---------|
| **技术实现路径** | 1. 在 QingTian 后端添加 NamespaceManager 组件，负责租户项目与 K8s Namespace 的映射管理<br>2. 项目创建时自动创建 Namespace、ResourceQuota，并打上 Tenant/Project Label<br>3. 集成 Kubernetes NetworkPolicy API，根据项目隔离策略自动生成网络规则<br>4. 使用 K8s 原生 RBAC 进行权限绑定，实现租户间权限隔离<br>5. 项目删除时级联清理 Namespace 及所有关联资源 |
| **所需资源** | - 开发：1 名后端工程师 × 2 周<br>- 测试：需要多租户 K8s 集群环境（3 节点 + Calico CNI）<br>- 依赖：Kubernetes 1.22+、Calico/Cilium CNI 插件 |
| **潜在风险** | 1. **权限提升风险**：Operator 需要 cluster-admin 权限，需最小权限原则重构<br>2. **NetworkPolicy 兼容性**：不同 CNI 插件对 NetworkPolicy 支持度不同，需适配<br>3. **资源泄漏**：项目删除时 Namespace 回收不完整导致资源泄漏<br>4. **性能影响**：大量 Namespace 对 Etcd 存储压力增加 |
| **风险应对** | 1. 使用 Credential 分离，Operator 使用受限的 ClusterRole<br>2. 做 CNI 兼容性检测，不支持时降级关闭网络隔离<br>3. 使用 OwnerReference 级联删除，依赖 K8s 原生垃圾回收<br>4. 监控 Etcd 尺寸，设置租户数量告警阈值 |

**具体实现方案**：
```go
// 多租户隔离核心实现结构
type TenantIsolationManager struct {
    k8sClient kubernetes.Interface
    recorder  record.EventRecorder
}

type WorkspaceSpec struct {
    TenantID       string            `json:"tenantId"`
    ProjectID      string            `json:"projectId"`
    GPUQuota       int               `json:"gpuQuota"`
    MemoryQuota    string            `json:"memoryQuota"`
    NetworkIsolate bool              `json:"networkIsolate"`
    Whitelist      []string          `json:"whitelist"` // 允许通信的项目
}

// 创建隔离工作空间
func (m *TenantIsolationManager) CreateWorkspace(ctx context.Context, spec *WorkspaceSpec) (*v1.Namespace, error) {
    // 1. 创建 Namespace
    ns := m.buildNamespace(spec)
    ns, err := m.k8sClient.CoreV1().Namespaces().Create(ctx, ns, metav1.CreateOptions{})
    if err != nil {
        return nil, err
    }

    // 2. 创建 ResourceQuota
    rq := m.buildResourceQuota(spec, ns.Name)
    _, err = m.k8sClient.CoreV1().ResourceQuotas(ns.Name).Create(ctx, rq, metav1.CreateOptions{})
    if err != nil {
        m.DeleteWorkspace(ctx, ns.Name)
        return nil, err
    }

    // 3. 创建 NetworkPolicy（如果启用隔离）
    if spec.NetworkIsolate {
        err = m.createNetworkPolicies(ctx, ns.Name, spec)
        if err != nil {
            m.DeleteWorkspace(ctx, ns.Name)
            return nil, err
        }
    }

    // 4. 创建 RBAC RoleBinding
    err = m.createRBAC(ctx, ns.Name, spec.TenantID)
    if err != nil {
        m.DeleteWorkspace(ctx, ns.Name)
        return nil, err
    }

    return ns, nil
}
```

```go
type ImageBuilder struct {
    k8sClient  kubernetes.Interface
    harborClient *harbor.Client
    config     BuilderConfig
}

type BuildRequest struct {
    GitURL     string `json:"gitUrl"`
    GitRef     string `json:"gitRef"`
    Dockerfile string `json:"dockerfile"`
    Context    string `json:"context"`
    ImageName  string `json:"imageName"`
    Tag        string `json:"tag"`
}

func (b *ImageBuilder) StartBuild(ctx context.Context, req *BuildRequest) (*BuildInfo, error) {
    // 1. 创建构建 Pod 使用 Kaniko
    pod := b.createKanikoPod(req)
    pod, err := b.k8sClient.CoreV1().Pods(b.config.Namespace).Create(ctx, pod, metav1.CreateOptions{})
    if err != nil {
        return nil, err
    }

    // 2. 等待构建完成（异步）
    go b.waitBuildCompletion(pod.Name, req)

    // 3. 返回构建信息，前端通过 WebSocket 看日志
    return &BuildInfo{
        BuildID: pod.Name,
        Status:  "building",
    }, nil
}

// 构建完成后触发漏洞扫描
func (b *ImageBuilder) afterBuild(req *BuildRequest) error {
    // 触发 Harbor 扫描
    overview, err := b.harborClient.ScanImage(req.ImageName, req.Tag)
    if err != nil {
        return err
    }

    // 检查漏洞，如果有严重漏洞阻止后续流程
    if overview.HasCriticalVulnerabilities() {
        // 标记构建为失败
        return fmt.Errorf("image has critical vulnerabilities, blocking")
    }

    // 安全通过，触发下一个流水线步骤
    return b.triggerNextStep(req)
}
```

```go
// 数据集版本管理器
type DatasetManager struct {
    dvcRepo  string
    storage  Storage
    metaDB   MetadataDB
}

type DatasetVersion struct {
    VersionID   string    `json:"versionId"`
    DatasetID   string    `json:"datasetId"`
    Hash        string    `json:"hash"` // 内容哈希
    Size        int64     `json:"size"`
    CreatedAt   time.Time `json:"createdAt"`
    CreatedBy   string    `json:"createdBy"`
    Description string    `json:"description"`
}

// 创建新版本
func (m *DatasetManager) CreateVersion(ctx context.Context, dsID string, localPath string) (*DatasetVersion, error) {
    // 1. DVC add
    if err := m.dvcAdd(localPath); err != nil {
        return nil, err
    }

    // 2. DVC push 到远程存储
    if err := m.dvcPush(); err != nil {
        return nil, err
    }

    // 3. 计算哈希，保存元数据
    hash, err := m.computeHash(localPath)
    if err != nil {
        return nil, err
    }

    version := &DatasetVersion{
        VersionID: uuid.New().String(),
        DatasetID: dsID,
        Hash:      hash,
        CreatedAt: time.Now(),
    }

    // 4. 保存元数据到数据库
    return version, m.metaDB.SaveVersion(version)
}

// 检出指定版本
func (m *DatasetManager) Checkout(ctx context.Context, dsID string, versionID string) error {
    version, err := m.metaDB.GetVersion(dsID, versionID)
    if err != nil {
        return err
    }
    // dvc checkout 到对应版本
    return m.dvcCheckout(version.Hash)
}
```

#### 2.7 弹性伸缩（HPA/VPA）

| 属性 | 说明 |
|------|------|
| **现状** | 资源静态分配，无自动扩缩容 |
| **缺失原因** | 未实现基于队列长度或 GPU 利用率的伸缩策略 |
| **影响范围** | 高峰期任务排队，低峰期资源浪费 |

**详细需求**：

```yaml
# 弹性伸缩配置
features:
  # 1. 水平伸缩（HPA）- 基于队列长度
  hpa:
    triggers:
      - type: queue-length
        metric: scheduler.queue.length
        target: 10  # 队列长度超过10则扩容
        scaleUpStep: 2  # 每次扩容2个节点
      - type: gpu-utilization
        metric: node.gpu.utilization
        target: 80%
        scaleDownDelay: 10m  # 10分钟后才缩容
    limits:
      minNodes: 3
      maxNodes: 100

  # 2. 垂直伸缩（VPA）- 基于历史资源使用
  vpa:
    recommendationMode: Auto
    updateMode: Initial  # 仅在 Pod 创建时调整，运行中不重启
    resources:
      cpu:
        minAllowed: 100m
        maxAllowed: 4
      memory:
        minAllowed: 256Mi
        maxAllowed: 64Gi

  # 3. 预测性伸缩（基于历史模式）
  predictive:
    enabled: true
    model: "time-series-forecasting"  # 使用时间序列预测
    horizon: "1h"  # 预测未来1小时负载
    trainingData: "30d"  # 使用30天历史数据训练
```

**详细技术实现分析**：

| 分析维度 | 具体内容 |
|---------|---------|
| **技术实现路径** | 1. 开发 ClusterAutoscaler 扩展器，基于 QingTian 队列长度和 GPU 利用率决策扩缩容<br>2. 对接云厂商 API（如 AWS ASG、阿里云 ECI）实现节点池弹性伸缩<br>3. 集成 Kubernetes VPA 实现垂直伸缩建议，调度时使用建议值<br>4. 基于历史负载数据训练 ARIMA/LSTM 时间序列预测模型<br>5. 预测未来负载，提前扩容避免排队 |
| **所需资源** | - 开发：1 名后端工程师 × 4 周<br>- 依赖：Kubernetes ClusterAutoscaler、云厂商 API 权限<br>- 数据：需要至少 2 周历史数据训练预测模型 |
| **潜在风险** | 1. **扩缩容抖动**：频繁扩缩容增加云成本，影响稳定性<br>2. **预测不准**：突发负载预测错误导致扩容不及时<br>3. **权限风险**：需要云厂商 API 权限，权限范围大<br>4. **缩容失败**：缩容时无法正确排空节点导致任务失败 |
| **风险应对** | 1. 设置扩容冷却（5 分钟）和缩容延迟（10 分钟），避免抖动<br>2. 预测+反应式结合，预测失败时快速 fallback 到反应式扩容<br>3. 使用 IAM 角色限制权限，仅允许伸缩指定节点池<br>4. 严格的 PDB（PodDisruptionBudget）保护，排空失败中止缩容 |

**具体实现方案**：

```go
// 水平伸缩控制器
type HorizontalScaler struct {
    cloudClient CloudProviderClient
    config      AutoScalingConfig
    metrics     MetricsClient
}

type ScalingDecision struct {
    Action      string `json:"action"` // scale_up / scale_down / none
    TargetNodes int    `json:"targetNodes"`
    Reason      string `json:"reason"`
}

// 做出扩缩容决策
func (s *HorizontalScaler) MakeDecision(ctx context.Context) (*ScalingDecision, error) {
    // 获取当前指标
    queueLen, err := s.metrics.GetSchedulerQueueLength()
    if err != nil {
        return nil, err
    }

    utilAvg, err := s.metrics.GetAverageGPUUtilization()
    if err != nil {
        return nil, err
    }

    currentNodes, err := s.cloudClient.GetCurrentNodeCount()
    if err != nil {
        return nil, err
    }

    // 根据策略决策
    switch {
    case queueLen > s.config.QueueLengthTarget && currentNodes < s.config.MaxNodes:
        // 需要扩容
        targetNodes := min(currentNodes + s.config.ScaleUpStep, s.config.MaxNodes)
        return &ScalingDecision{
            Action:      "scale_up",
            TargetNodes: targetNodes,
            Reason:      fmt.Sprintf("queue length %d > target %d", queueLen, s.config.QueueLengthTarget),
        }, nil

    case utilAvg < s.config.UtilizationTarget && currentNodes > s.config.MinNodes && s.canScaleDown():
        // 需要缩容
        targetNodes := max(currentNodes - s.config.ScaleDownStep, s.config.MinNodes)
        return &ScalingDecision{
            Action:      "scale_down",
            TargetNodes: targetNodes,
            Reason:      fmt.Sprintf("utilization %.1f%% < target %.1f%%", utilAvg, s.config.UtilizationTarget),
        }, nil

    default:
        return &ScalingDecision{
            Action:      "none",
            TargetNodes: currentNodes,
            Reason:      "no action needed",
        }, nil
    }
}

// 预测性伸缩
type PredictiveScaler struct {
    model TimeSeriesModel
}

func (s *PredictiveScaler) Predict(ctx context.Context, history []MetricPoint, horizon int) ([]Prediction, error) {
    // 使用 ARIMA 或 Prophet 预测未来负载
    // 根据预测结果提前调整节点数
    return s.model.Forecast(history, horizon)
}
```
