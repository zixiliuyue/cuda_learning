## 核心概念

### 两大流派对照

| 维度 | 非结构化剪枝 | 结构化剪枝 |
|------|-------------|-----------|
| 粒度 | 单个权重 | 整通道/整神经元/整行列 |
| 结果 | 稀疏矩阵（带很多 0） | 更小的稠密矩阵 |
| 重要性度量 | `|w|` 幅值 | 通道 L2 范数 / BN 的 gamma |
| 精度损失 | 同稀疏度下更小 | 同压缩率下通常更大 |
| 硬件加速 | 需专用稀疏 kernel（如 Ampere 2:4） | 任意硬件直接受益 |
| 模型是否变小 | 否（只是变 0） | 是（参数真实减少） |

### 非结构化剪枝：按幅值置零

对权重矩阵，把绝对值最小的一批权重设为 0（幅值小≈贡献小）。用「掩码」记录哪些位置被剪，微调时每步更新后重新套用掩码，保持这些位置恒为 0：

```python
threshold = torch.kthvalue(w.abs().flatten(), k).values  # 第 k 小的幅值
mask = (w.abs() > threshold).float()                     # 1=保留, 0=剪掉
w.mul_(mask)
```

### 结构化剪枝：删整个神经元

用每个输出神经元（权重矩阵的一行）的 L2 范数衡量重要性，只保留 top-k 个神经元，并**真的重建**更小的层：删掉 `fc2` 的输出行，同时删掉 `fc3` 对应的输入列。结果是一个参数更少的稠密模型，任何硬件都能直接加速。

### 关键范式：train → prune → fine-tune

直接大比例剪枝往往掉点（实验里 95% 稀疏度精度从 96% 掉到 48%），但**微调**让剩余权重重新适配后能追回大部分精度（回到 93%+）。可迭代进行：剪一点 → 微调 → 再剪 → 再微调。

## 知识点总结

1. **非结构化剪枝**：按 `|w|` 幅值置零，稀疏度高、精度损失小，但需专用稀疏 kernel 才能加速。
2. **结构化剪枝**：删整通道/神经元，模型真实变小，任意硬件受益，但粒度粗、掉点更多。
3. **重要性度量**：非结构化用 `|w|`；结构化常用通道 L2 范数或 BN 的 gamma 系数。
4. **微调是关键**：`train → prune → fine-tune` 是恢复精度的标准范式，可迭代执行。
5. **半结构化稀疏**：NVIDIA Ampere 的 2:4 稀疏（每 4 个里保留 2 个）兼顾精度与硬件加速。

## 动手挑战

1. **迭代剪枝**：把一次剪到 95% 改成「每轮剪 20% + 微调」重复多轮，对比最终精度。
2. **换重要性度量**：结构化剪枝里把 L2 范数换成 L1 范数或「激活值均值」，看排序是否变化。
3. **全局 vs 逐层**：非结构化剪枝改成「全局阈值」（所有层权重放一起排序），对比逐层剪枝的效果。
4. **真稀疏加速**：在支持 2:4 稀疏的 GPU 上用 `torch.sparse` 或 cuSPARSELt 测量真实加速比。

## 常见问题

- **Q：剪枝后模型文件为什么没变小？**
  A：非结构化剪枝只是把权重变 0，形状不变，需配合稀疏存储格式（CSR 等）或专用硬件才省空间/时间；结构化剪枝才会真正减小参数量。

- **Q：为什么用幅值当重要性？**
  A：这是最简单有效的启发式（Magnitude Pruning）。更高级的有基于二阶信息（OBD/OBS）、梯度、Taylor 展开等方法。
